# Irisync アプリ実装 Issue 一覧

[基本設計](basic-design.md)と[実装計画](implementation-plan.md)の A01〜A09 を、個別にレビュー・検証できる18件に分割した実装計画。A で始まる ID は計画上の識別子で、先行欄には直接の依存だけを記載する。D で始まる番号は基本設計の詳細設計項目を指す。

## 実装順序

1. A01 で Go の実行入口と CI を用意する。次に設定・状態管理とファイル走査・SSH 接続を並行して進め、A04-3 で単一ペアの双方向同期を実機で確認する。
2. A05 で変更監視と定期走査を組み合わせる。A06 で複数ペアの運用と復旧を実装し、設定変更と履歴・メトリクスは A06-1 の完了後に並行して進める。
3. A07-1 の基本 API が揃ったら、詳細 API とダッシュボードの開発を並行する。A08-2 で画面と配布形態を統合し、A09 で Windows・Linux の実機試験と配布確認を行う。

## Project のステータスと着手順

起票時点では、C07 は `Done`、A01 は `Backlog`、後続17件は `Pending` とした。アプリ実装を開始する際に A01 を `Ready` にする。各 Issue の直接の依存は本文の「先行Issue」と GitHub の `Blocked by` に登録済み。[Irisync Project #4](https://github.com/users/coco-papiyon/projects/4)

先行 Issue がすべて同じ Project で `Done` になったことを Conductor がプログラムで確認し、`Pending` から `Ready` に進める。D 項目は各 Issue の詳細設計で確定し、承認後に実装する。[Conductor 実現可能性検討](conductor-feasibility-study.md)
