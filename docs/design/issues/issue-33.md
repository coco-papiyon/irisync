# Issue #33 [A03-2] OpenSSH 経由の Agent 接続とリモート走査の詳細設計

## 目的・範囲

コントローラーが OpenSSH でリモート Agent を起動し、ホスト鍵の検証、標準入出力での互換性確認、指定ルートの再帰走査を行う。Windows と Linux を対象とし、接続の成立から初回走査の完了まで、互換性エラー、走査中の切断、Agent 専用受信ポートなしでの動作を検証する。ここでの初回走査は SSH セッション確立後の最初の走査を指す。 [Issue #33](https://github.com/coco-papiyon/irisync/issues/33) · [基本設計 §2–4](https://github.com/coco-papiyon/irisync/blob/main/docs/design/basic-design.md) · [実装計画 §2.1 A03](https://github.com/coco-papiyon/irisync/blob/main/docs/design/implementation-plan.md)

## 実装計画

1. **設定と OpenSSH 起動（R1–R5、R15–R16）**。既存のコントローラー CLI・設定読込に接続処理をつなぐ。ローカル側はシェルを介さず `ssh` に引数を渡し、Agent 起動は非 PTY の固定コマンドとする。リモート走査ルートは交渉後の要求で渡す。SSH 側の診断出力はプロトコル入力と分け、外部に返すエラーを分類する。
2. **stdio セッションと交渉（R4–R7、R12、R14）**。コントローラーと Agent の起動点から共用できるプロトコル処理を実装する。D-13 の初期案は、上限付きの長さ付きフレームに交渉、走査要求、結果、正常完了、エラーを載せる方式とする。走査は1セッションで同時に1件、圧縮なしから始め、異常フレームと完了前 EOF は失敗にする。
3. **Agent 走査ハンドラー（R8–R12、R16）**。先行実装の走査・パス検証へ接続し、正常完了を受けた結果だけをコントローラーの呼び出し元へ引き渡す。Go のパッケージ名・ファイル名は先行実装の配置と公開 API を確認して決める。
4. **切断処理と運用接続点（R12–R14）**。切断時は進行中の走査を中断し、Agent と SSH セッションの終了を処理する。接続異常をペア状態へ渡す部分は既存の状態 API があれば接続し、未整備の場合は A06 が `reconnecting` を適用できる失敗通知とする。D-03 の提案として、接続、交渉、走査応答の待機を区別して扱う。

## 復旧手順

1. **ホスト鍵エラー**。接続先の鍵を管理者が別経路で照合する。初回登録または正当な鍵交換を確認してから信頼済みホスト鍵を更新し、接続・交渉・走査をやり直す。
2. **互換性エラー**。報告されたバージョンと機能を確認し、承認済みの互換 Agent またはコントローラーへ切り替える。新規セッションで交渉と走査を確認する。
3. **走査中の切断**。中断した結果を破棄し、SSH 子プロセスを回収する。この Issue の再試験では新規セッションを開始し、Agent の起動と交渉から走査をやり直す。A06 の運用復旧では、自動再接続後に A/B 双方の全体走査を完了してから同期を再開する。 [基本設計 §3.3、§17](https://github.com/coco-papiyon/irisync/blob/main/docs/design/basic-design.md) · [実装計画 §2.1 A06](https://github.com/coco-papiyon/irisync/blob/main/docs/design/implementation-plan.md)

## #33 の実装で確定した接続契約

- 第1版は4バイトのビッグエンディアン長に UTF-8 JSON を続ける。ペイロードは最大64 KiB、1走査の応答は最大256 MiB。双方でバージョン1と `scan-sha256` を確認する。ファイルと問題を別フレームで返し、明示的な完了フレームを受け取った走査だけを呼び出し元へ渡す。問題には種類とパスを含め、元の OS エラーは送らない。
- 接続には OpenSSH の `ConnectTimeout=15` を使い、接続・交渉の全体を30秒、走査要求から完了までを5分に制限する。タイムアウトとキャンセルでは stdio を閉じて SSH を終了し、子プロセスを回収する。
- SSH 設定方式は OpenSSH のホストエイリアスを使う。直接指定方式は `-F none` で構成を分け、省略ポートは22。どちらも登録済みのホスト鍵を要求し、非対話、PTY なし、接続共有なしで `irisync-agent --stdio` を起動する。リモートルートは交渉後に stdio で送る。Agent の実行名は Windows と Linux で共通で、Windows のファイルには `.exe` を付ける。
- `controller scan-remote` は設定済みの1ペアを対象とする。Agent は #32 の `scan.Scan` で指定された絶対ルートだけを走査する。複数の SSH エイリアスをまたぐリモート実体の重複検査と、ペア状態への自動再接続の反映は、複数ペアを起動する A06 に引き継ぐ。
