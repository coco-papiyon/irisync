# [A02-1] YAML 設定とペア定義の検証 — 設計・実装計画

## 目的と範囲

Go コントローラーの起動時に YAML、既定値、環境変数から設定を組み立て、全ペアの検証に成功した設定だけを後続処理へ渡す。各ペアは、ID、ローカルルート、リモートルート、SSH 接続先、除外 glob、起動方針を持つ。SSH 接続情報は OpenSSH の設定を参照する方式と直接指定方式を表現できるようにする。

本 Issue は設定の読込と静的検証を担当する。SQLite のスキーマと希望稼働状態の永続化は A02 の状態管理、SSH 接続とエージェント起動は A03、除外 glob の同期処理への適用は A05、動的再読込と稼働ペアの再構築は A06 で扱う。 [基本設計 §2–4、§7、§11–13](../basic-design.md) · [実装計画 §2.1](../implementation-plan.md)

## 依存関係

- 直接の先行 Issue は **#29**。記載された完了条件を満たした後、A01 で整備されるコントローラーの設定読込の土台と Windows/Linux の検証環境に接続する。
- A02 の状態管理へ、検証済みのペア ID と起動方針を渡す。静的検証は SQLite や SSH 接続から独立させる。 [実装計画 §2.1](../implementation-plan.md)

## 設計と実装手順

1. **設定の入力と型を定義する。** YAML を型付きの設定に読み込み、構文エラー、型違い、必要項目の欠落を検出する。ペアごとに空でない ID、両ルート、有効な接続指定を求める。接続方式に応じて項目の組み合わせを確認し、除外 glob は後続の適用処理と同じ構文で検証できる契約にする。診断には項目名とペアの位置を使い、入力値の生データを含めない。
2. **設定値を確定してから検証する。** 本計画では、環境変数による上書きを許可した項目について、既定値、YAML、環境変数の順に適用する。環境変数の対象項目と名前、`startup` 省略時の扱い、glob の詳細構文は提示資料で未確定のため、実装時に設定仕様とテストに明記する。未指定と明示値を区別し、空値や型違いを既定値で隠さない。最大ファイルサイズの全体既定値は `1GiB` とし、ペア別の明示値が優先する。`0` は無制限として保持する。全体走査間隔や同時実行数の例示値は暫定として扱う。
3. **起動方針を型付きで返す。** `start` は起動時の開始要求、`stop` は停止、`restore` は保存済みの希望稼働状態の復元を表す。状態管理側では、`restore` の履歴がなければ停止とし、保存済みの希望状態から実行状態を再構築する。設定読込では値を解釈し、起動や状態更新は呼び出し側に委ねる。
4. **全ペアを横断して ID とルートを検証する。** 同一 ID を拒否する。ローカルはコントローラーの OS のパス規則に従い、区切りや末尾区切り、`.` などの字句上の表記差を正規化する。リモートは接続指定から同一接続先と判定できる範囲で、リモート側のパス形式に従って同じ比較を行う。比較はパス要素単位で行い、同一または親子関係なら、登録順にかかわらず拒否する。リモートにコントローラー側の OS 規則を流用せず、SSH エイリアスの別名やリンク・ジャンクションなどを経由した実体の衝突は起動検査に引き継ぐ。
5. **起動経路に組み込む。** 設定全体が有効な場合にだけ、確定済みの設定を後続処理へ渡す。エラーには修正箇所が分かる情報を添える。 [基本設計 §2.3、§3.1、§4.1、§7、§12–13、§16、§19](../basic-design.md)

### 同期ルートの文字と比較範囲

- ルートには日本語を含む Unicode の文字や、空白、括弧、`&`、`+` などローカル・リモートそれぞれの OS が許可する記号を使える。Windows の禁止文字、予約デバイス名、パス要素の末尾のドット・空白は拒否する。
- Windows の静的なルート比較では、区切り文字を正規化し、ASCII 英字 `A–Z`・`a–z` の大小を同一視する。非 ASCII 文字は記述どおりに比較し、大小文字変換と Unicode 正規化は行わない。例えば `K` と `k` は同じ要素、`K` と `K` は異なる要素として扱う。POSIX パスの静的比較では文字の大小を区別する。
- ファイルシステム固有の規則で別表記が同じディレクトリを指す場合は、ペアの起動検査で確認する。実体が同一または親子関係にある場合は、該当ペアの同期を開始しない。

## 受入条件と検証方法

| 検証ケース | 期待結果 |
| --- | --- |
| `start`、`stop`、`restore` を個別に指定 | 各値が開始要求、停止、希望状態の復元に対応する。状態管理との結合時に `restore` の履歴ありと履歴なしを確認し、履歴なしでは停止する。 |
| YAML の構文・型エラー、未知の起動方針、必須項目の欠落、不正な接続指定・除外 glob・環境変数値 | 修正箇所が分かるエラーを返し、設定全体を拒否する。 |
| 同一 ID を複数ペアに指定 | ルートが異なっていても拒否する。 |
| ローカル、または同一と判定できるリモート接続先で、同一ルート・表記違いの同一ルート・親子ルートを指定 | いずれも拒否する。親子の登録順を逆にしても結果は同じになる。 |
| `/data/a` と `/data/ab`、または異なる接続先に同じリモートパスを指定 | 他の項目が有効なら受理する。 |
| 日本語、空白、括弧、`&`、`+` を含む有効なルートを指定 | 受理する。日本語を含む同一ルートや親子ルートは拒否する。 |
| Windows の同一接続先で ASCII 英字だけの大小違い、非 ASCII 文字の大小違い、Unicode 正規化による表記違いを指定 | ASCII 英字だけの大小違いは静的検査で重複と判定する。非 ASCII の別表記は記述どおりに比較し、実体の照合は起動検査で行う。 |
| 許可した項目で既定値、YAML、環境変数を組み合わせる | 規定の優先順で値が決まる。最大ファイルサイズは全体既定値、ペア別上書き、明示的な `0` を区別する。 |

設定読込のテストとコントローラー起動経路のテストで、Windows/Linux のパス規則と、エラー時に設定が部分適用されないことを確認する。

## 障害時の復旧

- **初回読込に失敗した場合**は、設定を有効化せず、ペアの起動や希望状態の更新に進まない。該当する YAML 項目または環境変数を修正し、設定全体を再検証してから起動する。
- **実体の衝突が起動検査で判明した場合**は、該当ペアの起動を止める。ルートまたは接続指定を修正し、静的検証と起動検査をやり直す。
- **後続の動的再読込で検証に失敗した場合**は、稼働中の設定を維持する。候補設定を修正し、全体の検証を通過した後に切り替える。 [基本設計 §2.3、§12.1](../basic-design.md) · [実装計画 §2.1](../implementation-plan.md)
