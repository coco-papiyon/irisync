# [A03-1] 安全なパス処理とローカル走査の設計・実装計画

## 作業範囲

Windows/Linux の Go 実装で、同期ルートを境界とするパス検証と再帰的なローカル走査を提供する。同期候補となる通常ファイルについて、ルート相対パス、バイト単位のサイズ、更新時刻、内容の SHA-256 を取得する。ディレクトリは走査と名前衝突の判定に使用する。走査は読み取り専用とする。

D-18 のうち、OS ごとのパス表現、名前の互換性、リンクと再解析ポイントの扱い、走査で取得する更新時刻の検証を扱う。監視、ファイル置換、更新時刻の反映、SSH 接続、同期判定、SQLite への基準保存は後続工程で扱う。転送サイズ上限は A04、ペア別の除外 glob と定期走査は A05 で扱う。

## 設計・実装手順

1. **ルート相対パスの契約を定義する。** 内部識別子は `/` 区切りで元の大小文字を保持し、OS 固有のパスへ変換する前に各要素を検証する。空パス、空要素、`.`、`..`、絶対パス、ドライブ指定、UNC 形式、および区切りとして解釈され得るバックスラッシュを拒否する。外部入力を正規化して有効なパスへ変える前に、元の入力を検査する。
2. **ファイルシステム上でルート境界を強制する。** 検証済みのルートディレクトリを起点に、各中間ディレクトリと最終要素をルートに固定した操作で開く。リンクを追跡せず、Windows の再解析ポイントは種類を問わず除外し、該当するディレクトリ配下へ降りない。走査開始時の検査に加え、実際に開く段階でも境界と種別を保証する。必要な保証を得られない場合は対象の読み取りを中止する。具体的な OS API は A01 の Go 実行基盤に合わせて選定する。
3. **名前の互換性を検査する。** 各要素について Windows の禁止文字・予約名・末尾ドットや空白を検査する。同一親ディレクトリ内のファイル名とディレクトリ名を、Windows での大小文字を区別しない比較に基づいて照合する。衝突した要素はすべてエラーにし、衝突したディレクトリ配下も同期候補から外す。元の名前は相対パスに保持する。
4. **メタデータと走査結果を返す。** 安全に開いた通常ファイルからサイズと更新時刻を取得し、同じファイルをストリームで読み取って SHA-256 を計算する。読み取り後にサイズ・更新時刻とパスが指す実体を再確認し、検出した変更は再走査対象とする。更新時刻は表示用の文字列へ丸めず時刻値として扱い、検証時はファイルシステムが返す精度を基準にする。結果では取得成功、除外、名前エラー、読み取り失敗、未走査範囲を識別できるようにする。[基本設計](https://github.com/coco-papiyon/irisync/blob/main/docs/design/basic-design.md)

### ローカル走査の実装

- `internal/scan.Scan` はファイルのメタデータと、除外・名前エラー・衝突・読込失敗・変更・未走査の情報を返す。各問題は報告されたパスとその配下に適用する。ルートを開けない場合や走査を中断した場合はエラーを返す。後続処理は未確認の範囲を削除判定に使わない。
- ルート指定の `..` とドライブ相対パスは絶対パス化の前に拒否する。`link/../dir` を字句上の別のパスに変換すると、指定先と異なるディレクトリを走査し得る。
- Linux はルートのファイルディスクリプタを基点に `openat2` で探索し、子のシンボリックリンクとマウント境界を越えない。通常ファイルとディレクトリだけを、確認済みのディスクリプタから読み取り用に開く。`openat2` を使える Linux カーネルと `/proc/self/fd` が必要。[openat2](https://man7.org/linux/man-pages/man2/openat2.2.html)
- Windows はディレクトリハンドルを基点に `NtCreateFile` で開き、経路と最終要素の再解析ポイントを除外する。読み取った名前はシステムの大小文字を区別しない序数比較で照合する。[OBJECT_ATTRIBUTES](https://learn.microsoft.com/en-us/windows/win32/api/ntdef/ns-ntdef-_object_attributes)
- Linux の走査でも、Windows の禁止名と大小文字の衝突を検出する。Linux は Windows の序数比較で使われる大文字化に合わせたテーブルを用い、`Ä` と `ä` などの衝突を検出する。このテーブルには Windows 上で取得した UTF-16 コード単位の変換を記録し、Windows で `go generate ./internal/scan` を実行すると更新できる。転送先のファイルシステム固有の衝突は転送時にも確認する。[CompareStringOrdinal](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-comparestringordinal) · [RtlUpcaseUnicodeChar](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-rtlupcaseunicodechar)

## 受入条件と検証方法

| 検証項目 | 合格条件 |
| --- | --- |
| 正常走査 | Windows/Linux で入れ子の通常ファイルと空ファイルを走査し、相対パス、バイト数、ファイルシステムから取得した更新時刻、既知内容の SHA-256 が一致する。 |
| ルート外参照 | 親ディレクトリ参照、絶対パス、ドライブ指定、UNC 形式を拒否する。走査中に経路の要素がリンクへ差し替わった場合も、ルート外の内容を読み取らない。 |
| リンクと再解析ポイント | ルート内外を指すシンボリックリンクを除外する。Windows ではジャンクションを含む再解析ポイントを除外し、その配下を走査しない。 |
| Windows の名前互換性 | 拡張子付きの予約名、禁止文字、末尾ドット・空白を名前検証テストで拒否する。大小文字だけが異なるファイル名・ディレクトリ名は、両方を作成できる環境で走査し、衝突した候補がすべてエラーになることを確認する。 |
| 不完全な走査 | 読み取り不能、走査中の消失・更新、中断を検証し、影響範囲が削除候補や確定済みのメタデータとして扱われないことを確認する。 |

## 復旧時の扱い

- 無効なルートやルートを開けない場合は、そのルートの走査を失敗として返す。途中でアクセス不能になった範囲は未確認として返し、安全に走査できる範囲の処理を続ける。
- 読み取り中にファイルの変更や消失を検出した場合は、その取得結果を破棄する。次回の走査でパス検証からやり直す。無効名や大小文字衝突は原因が解消された後の走査で再評価する。
- 中断・異常終了後はルートから再走査し、未確認・除外・エラーを削除判定に使わない。最終同期基準と初期同期完了状態の更新は、後続の同期処理で成功を確認した時点に委ねる。
